# Context in a browser

This is a private browser client for the same encrypted Context ledger used by the Android and iPhone app. Its portable `shared` directory contains exact reviewed snapshots of the phone's batch validation, revision ordering, AES-GCM/PBKDF2 envelope, and spreadsheet text parser. `shared/source-manifest.json` records every hash; the build verifies the snapshot and, when the monorepo is present, compares it with the live phone sources. The mobile source and native dependencies are unchanged by this browser client.

This folder builds independently: install its pinned dependencies with `pnpm install --frozen-lockfile`, then run `pnpm test`, `pnpm typecheck`, and `pnpm build`. Refresh a protocol snapshot only from reviewed mobile source with `node scripts/snapshot-phone-protocol.cjs`. The existing Sites project is recorded in `.openai/hosting.json`; deploy `dist` through the site's owner-only visitor gate. The public Google Web client ID is configuration, not a secret. Register the exact HTTPS site origin on that existing Google Cloud client before connecting. No server OAuth client secret is needed for this user-initiated GIS token flow.

Google access tokens and the ledger passphrase stay in memory. IndexedDB stores an account-subject-scoped, authenticated encrypted cache with optimistic generation checks; it never stores the passphrase or Google token. Lock clears the in-memory secrets. Browser data can still be removed by the browser, its user, storage eviction, or private browsing; successful private-ledger synchronization is the cross-device copy. The browser prompts for fresh authorization when Google's short-lived token expires; background synchronization never opens a sign-in popup.

A new browser downloads and decrypts the phone's existing batches before allowing edits. If no phone ledger is found, it asks the user to synchronize the phone first. Downloads precede uploads, immutable batches use preallocated Drive IDs for safe retries, losing note versions remain reviewable, and account switching never moves another account's local notes. Existing projections, activity groups, text formats, and categories are preserved. Calendar plans are optional and read-only in this client; calendar export still depends on explicitly authorized phone calendar synchronization.

Click a cell to select it and open the bottom text bar without opening the keyboard. Click its text box to type; the selected cell mirrors the raw text. The first checkmark saves the latest text and opens the formatting bar; the second closes that bar. Bold, italic, underline, text color, and Google Calendar fill colors apply to the selected rectangle. Hold or right-click cells for text Cut/Copy/Paste, Clear, and AutoFill when applicable. Ctrl+V/⌘V in the text box edits that text; on the grid it pastes a spreadsheet rectangle: rows are minutes and columns are consecutive dates, with a 31-day/10,000-cell/1,048,576-character bound. Pasting one text cell into a selected rectangle fills that rectangle. Each paste or format command uses one guarded local transaction, and Undo refuses to overwrite newer synchronized work. Formulas remain text; source spreadsheet styling is not imported.

This client uses IndexedDB rather than Expo SQLite on the web. It therefore needs no SharedArrayBuffer, cross-origin isolation, or OAuth popup bridge. The website's visitor authentication remains distinct from Google's calendar/app-folder authorization. No access token, plaintext ledger, or real user note belongs in public verification artifacts.
